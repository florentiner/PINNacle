# Проверка идеи «добавить сеть как бустинг» (arXiv 2307.08934) — 2026-08-11

Идея коллеги: multi-stage boosting (Wang & Lai: u = u0 + eps*u1, вторая сеть
доучивает остаток первой) как ещё одно действие пайплайна; момент добавления —
по ландшафту.

## Трек 1: офлайн-анализ RL-буферов (rlpinn-ablation-buffers)

312 файлов, 25 398 переходов (ns2d_liddriven, poisson3d_complexgeometry,
poisson_boltzmann_2d); state = 4-канальная лосс-ландшафтная карта 26x26,
reward ~ -(текущая ошибка).

Вопрос: предсказывает ли состояние, что оптимизаторные действия исчерпаны
("застой" = в следующих 5 действиях ни одно не даёт существенного улучшения;
таких состояний 23%)?

| Предиктор | AUC |
|---|---|
| Геометрия карты поодиночке (delta, flatness, roughness, std) | 0.45-0.53 (~случайность) |
| Уровень ошибки (reward) | 0.725 |
| Логистическая комбинация всех фич | 0.756 (по PDE: 0.756-0.771) |

Вывод: тонкая геометрия ландшафта сама по себе — слабый триггер; рабочий
сигнал — «ошибка низка и перестала падать» (+~0.03 AUC от геометрии сверху).
Практический триггер для добавления сети = плато лосса; это согласуется с
процедурой самой multi-stage статьи. (AUC in-sample; лог-регрессия на 25k
точек / 8 фич — оверфит незначителен.)

## Трек 2: онлайн MVP в chain_eval

Стадия {"boost_net": {hidden, eps}}: замораживает текущую сеть, оборачивает в
композит u = base + eps*boost (градиенты по входу текут через base — нужно для
PDE-невязки), eps="auto" = sqrt(текущего MSE невязки) — упрощение формулы
eps = RMS(r1)/(2*pi*f_d)^m из статьи (частотную оценку и линеаризацию
оператора не делаем — это полный MSNN, вне рамок MVP; наш вариант = greedy
additive boosting на исходном лоссе).

Конфигурации (бюджет 31k шагов, SOAP как базовый оптимизатор):
- boost50: SOAP 15.5k -> boost(64*3) -> SOAP rest
- boostplateau: SOAP до плато (EarlyStopping patience=3000) -> boost -> SOAP rest
- baseline: SOAP 31k (уже в csv_soap)

PDE: burgers_1d (сходится, floor 0.013), poissonnd (уже 1e-3 — тест пробития
пола), heat2d_multiscale (спектральный кейс — мультистейдж должен помогать
именно там). Сиды 42-44. Результаты: csv_boost/{pde}.csv (schema chain_l2re).

Инцидент по пути: burgers_1d/boostplateau сиды 42,43 «пропали» — оказался баг
resume-проверки (existing_seeds не фильтровала по chain_key при schema
chain_l2re; csv_boost — единственная папка с несколькими chain_key в одном
файле, и boost50-сиды маскировали отсутствие boostplateau-сидов). Починено
(fix в hf_results.py), сиды досчитаны. Merge при аплоаде ключует полно —
данные не терялись, только пропускались при resume.

## Трек 3: закрытие лазеек (по требованию «быть уверенным на 100%»)

### Позитивный контроль в режиме статьи (paper_control_1d.py)

1D Пуассон, u* = sin(2πx)+0.5·sin(4πx), float64, сеть 64³ (и 16² для _small),
SOAP 31k (+L-BFGS до сходимости в _lb-армах); бюджет арм равный. L2RE mean/3 сида:

| арм | l2re |
|---|---|
| single: SOAP 62k | 2.1e-2 |
| boost: SOAP 31k → FNN-буст → SOAP 31k | 6.8e-5 |
| boostf: то же, Fourier-буст | 8.3e-5 |
| single_lb: SOAP+L-BFGS (исчерпана) | 2.25e-6 |
| boost_lb: исчерпана + FNN-буст (свежий бюджет) | 2.21e-6 |
| **boostf_lb: исчерпана + Fourier-буст** | **9.7e-9** |
| single_lb_small (база 16²) | 3.6e-6 |
| boost_lb_small | 3.7e-6 |
| **boostf_lb_small** | **2.8e-8** |

Два реальных механизма выигрыша, оба воспроизведены нашей реализацией:
1. **Спектральное расширение** (эффект статьи): после ИСЧЕРПАННОГО stage-1
   (L-BFGS до плато) невязка высокочастотна; tanh-FNN её не берёт (spectral
   bias) — буст с Fourier-фичами пробивает пол на 2.5 порядка. Требует
   float64-запаса точности.
2. **Рескейл-рестарт**: если stage-1 застрял из-за масштаба лосса (SOAP-only
   на этой задаче: лосс стартует с ~1e4), пере-нормировка через eps даёт
   optimizer'у второй шанс — работает даже с обычным FNN (×300). С L-BFGS
   застревания нет и механизм не нужен.

### Расширенный бюджет на PINNacle (Kaggle, csv_boost)

burgers_1d, 62k шагов, 3 сида: SOAP62k 0.01346; 31k→FNN-буст 0.01380;
ε×0.1 0.01347; ε×10 0.01361; **Fourier-буст 0.03927 (хуже в 3 раза)**;
справка SOAP31k 0.01393. Удвоение бюджета −3%; никакой буст пол не пробивает;
спектральный механизм не работает — невязка на полу 0.013 не гладкая
высокочастотная структура, а шум оптимизационного плато (float32 + жёсткий
ландшафт), Fourier-фичи его лишь усиливают. (poissonnd-армы и рецепт с
per-stage L-BFGS — считаются.)

## Вывод

1. Бустинг-сеть в середине бюджета **не вредит и не помогает** при
   фиксированном общем бюджете 31k: все различия в пределах сидового шума,
   включая heat2d_multiscale, где мультистейдж-механика должна была бы
   проявиться сильнее всего.
2. Триггер «по ландшафту» офлайн-анализом не подтвердился: геометрия карты
   ~случайность (AUC 0.45-0.53), работает только «лосс низкий и на плато»
   (AUC 0.756). Плато-триггер онлайн (boostplateau) дал то же, что и
   фиксированная середина.
3. Полный MSNN-эффект статьи (пробитие пола точности) требует их полной
   процедуры: линеаризация оператора вокруг u0, спектральная оценка eps,
   существенно больший бюджет стадии 2. Greedy-бустинг «в лоб» внутри того же
   бюджета выигрыша не даёт — как направление для пайплайна действие
   «добавить сеть» в текущем виде не оправдано.
